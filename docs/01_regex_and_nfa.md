# 步骤1：ToyC 正则规则与合并 NFA

## 目标
根据词法规则构造 NFA，合并为一个自动机，最终转换为 DFA。对应代码 `src/main.cpp` 内 `Automaton` 的 `literal`、`charset`、`concat`、`alternate`、`star`、`add`、`determinize` 与 `minimize`。

## 规则

| 类别 | 正则式/字面量 | 输出种类 |
|---|---|---|
| 标识符 | `[_A-Za-z][_A-Za-z0-9]*` | `Ident` |
| 整数 | `0\|[1-9][0-9]*` | `IntConst` |
| 关键字 | `int void const if else while break continue return` | 单引号括起关键字 |
| 双字符运算符 | `== != <= >= && \|\|` | 单引号括起字符 |
| 单字符运算符 | `+ - * / % = < > !` | 单引号括起字符 |
| 界符 | `( ) { } ; ,` | 单引号括起字符 |
| 注释 | `//...` 或 `/*...*/` | 忽略，单独处理 |

注：整数规则不接受负号；`-3` 切成 `'-'` 与 `IntConst(3)`。`012` 根据最长匹配及词法规则切成 `0` 和 `12`，不会合并成一个整数。

## 实现
1. `literal` 对关键字/运算符逐字符串联 NFA 边。
2. `charset` 对字符集合构造一条转移边。
3. `concat` 将两个片段通过 ε 边连接；`alternate` 构造选择分支；`star` 构造 Kleene 闭包。
4. `add` 用总起点的 ε 边连接各规则 NFA 起点，接受状态记录 Token 类型及规则优先级。
5. 关键字规则早于标识符规则；**只有匹配长度相等时才使用优先级**。例如 `int` 识别为关键字，`integer` 识别为标识符。

## 结果文件
- `src/main.cpp`：可独立编译的完整实现，包含上述 NFA 构造代码。
- `docs/dfa_illustration.png`：关键字/标识符、整数、`<` 与 `<=` 的局部自动机示意图。
- `outputs/dfa_transitions.tsv`：**实际编译后程序导出的完整最小化 DFA 转移表**，首行包含列名，后续每行一个状态。`[start]` 表示初态；`accept` 为接受类别；其余为输入字符对应的下一状态。

## 实验现象解释
从 `<=` 状态可观察到：读到 `<` 时已可接受，但继续读到 `=` 时进入另一个接受状态，因而产生 `'<='` Token。关键字规则对应的接受状态同时有继续匹配字母数字的路径，例如 `int` 后续遇到 `e`，可能继续进入标识符接受状态。

注意：PNG 是便于理解的**局部示意图**，完整状态结构以程序导出的 TSV 为准。最小化实现使用接受标签保持的分区细化法；并非严格的 Hopcroft 算法实现。
